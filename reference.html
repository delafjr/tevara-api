Authentication

Login, register klien, profil, logout
POST /auth/register
PUBLIC
Register klien baru
Request Body
FieldTypeKeterangan
namestringREQNama kontak person
emailstringREQUnique, dipakai login
passwordstringREQMin 8 karakter
password_confirmationstringREQ
phone_numberstringOPT
company_namestringOPTNama instansi/perusahaan
client_typeenumREQEXTERNAL | INTERNAL
addressstringOPT
Response 201
{ user: {...}, token: "sanctum_token", role: "klien" }
Notes
Auto-assign role klien. Auto-create client_profiles row. Token langsung bisa dipakai tanpa login ulang.
POST /auth/login
PUBLIC
Login semua role
Request Body
FieldTypeKeterangan
emailstringREQ
passwordstringREQ
Response 200
{ user: {id, name, email, avatar_url}, token: "...", role: "..." }
Notes
Response juga return permissions[] untuk frontend tahu menu apa yang muncul.
GET /auth/me
ALL
Data user yang sedang login
Return user + role + profile extension (client_profiles / lecturer_profiles / student_profiles sesuai role). Dipakai di page load untuk hydrate state auth.
POST /auth/logout
ALL
Cabut token Sanctum
Hapus token current ($request->user()->currentAccessToken()->delete()). Return 204.

Master Data

Kategori, status, role tim, kategori task — CRUD oleh Pengurus
Semua master data mengikuti pola yang sama: GET /master/{resource} (list), POST (create), PUT /{id} (update), DELETE /{id} (delete). Body: name (required, string, unique). Hanya pengurus_tefa yang bisa write.
GET/master/proposal-categories
ALL
List kategori proposal
Seed: Web, Mobile, Desktop, IoT, Other. Dipakai di dropdown F-01.
GET/master/proposal-statuses
ALL
List status proposal (ordered)
Return berurutan: Draft→Submitted→Under Review→Revision Required→Approved→Rejected→Active→Testing→Handover→Completed. Dipakai untuk render timeline progress bar.
GET/master/project-roles
ALL
List role tim mahasiswa
Seed: UI/UX, Frontend, Backend, Fullstack, QA Tester. Dipakai di F-04.
GET/master/task-categories
ALL
List kategori task
Seed: Frontend, Backend, UI/UX, Testing, Documentation, Research. Dipakai di F-05.
POST/master/{resource}
pengurus_tefa
Tambah item master
FieldType
namestringREQ
PUT/master/{resource}/{id}
pengurus_tefa
Edit item master
Body: { name }. Return item yang diupdate.
DELETE/master/{resource}/{id}
pengurus_tefa
Hapus item master
Cek dulu apakah item sedang dipakai di proposal/task. Jika ya, return 422 dengan pesan "Tidak bisa dihapus, sedang digunakan."

Auth Pages

Halaman: /register (Klien)
POST/auth/register Submit form register klien
Data yang dikumpulkan dari form:
name, email, password, password_confirmation, phone_number, company_name, client_type (select), address

Setelah sukses: simpan token ke storage → redirect ke /dashboard
Halaman: /login (Semua Role)
POST/auth/login Submit form login
Data dari form: email, password

Setelah sukses: simpan token + role ke storage → redirect ke /dashboard/{role}

Role → route mapping:
klien → /dashboard/klien
pengurus_tefa → /dashboard/pengurus
dosen → /dashboard/dosen
mahasiswa → /dashboard/mahasiswa
jurusan → /dashboard/jurusan
Page load (semua halaman yang butuh auth)
GET/auth/me Hydrate auth state saat page load
Call saat app pertama kali load (App.jsx atau middleware router). Jika 401 → redirect ke /login dan hapus token dari storage.

Render tabel termin: no termin, jumlah, status badge, tombol upload bukti (klien) / tombol verifikasi (pengurus) / tombol unduh invoice (keduanya).
PATCH/proposals/{id}/payments/{paymentId}/proof Upload bukti transfer — form di modal (Klien)
Input di modal: payment_date (datepicker), payment_method (select), transfer_reference (text), proof (file input — preview gambar sebelum upload).
Kirim sebagai FormData.
Setelah sukses: update status badge termin → "Menunggu Verifikasi".
PATCH/proposals/{id}/payments/{paymentId}/verify Verifikasi bukti (Pengurus) — modal konfirmasi
Modal: tampilkan preview gambar bukti transfer, input verification_notes, tombol "Verifikasi" (hijau) dan "Tolak" (merah). Setelah sukses: update badge status.
GET/proposals/{id}/invoices/{paymentId}/pdf Unduh PDF invoice
Trigger dengan window.open(url) atau <a href="{url}" download>.
Backend return sebagai file stream dengan header Content-Disposition: attachment.
Halaman: /payments/verify (Pengurus — verifikasi terpusat)
GET/payments/pending Load semua pembayaran yang butuh verifikasi
Tampilkan sebagai tabel dengan kolom: kode proyek, nama klien, termin ke-, jumlah, tanggal bayar, aksi (lihat bukti + verifikasi/tolak).
